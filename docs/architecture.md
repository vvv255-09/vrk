# 🏗 Архитектура проекта

Проект построен по классическому паттерну **MVC (Model-View-Controller)**, что обеспечивает разделение бизнес-логики, пользовательского интерфейса и управления данными.

## 🧩 Компоненты системы

### 1. Model (Модели)
Представляют собой простые Java-классы (POJO), которые описывают сущности системы.
- `User`: Данные пользователя и его роль.
- `Product`: Информация о товаре, остатки и минимальный порог.
- `Order` и `OrderItem`: Структура заказа и конкретные позиции в нем.
- `Supplier`: Данные о поставщиках.
- `Receipt` и `Expense`: Документы о поступлении и списании товаров.

### 2. View (Представление)
Интерфейс полностью отделен от логики с помощью **JavaFX FXML**.
- **Разметка**: Файлы `.fxml` определяют структуру окон и панелей.
- **Стилизация**: Один общий файл `styles.css` управляет внешним видом всего приложения.
- **Динамика**: Интерфейс состоит из основного окна (`main.fxml`), в которое динамически подгружаются различные панели (продукты, пользователи, отчеты).

### 3. Controller (Контроллеры)
Связующее звено между Model и View. Контроллеры обрабатывают события (нажатия кнопок, ввод) и обновляют данные на экране.
- Примеры: `LoginController`, `ProductsPanelController`, `MainController`.

### 4. Data Access Layer (Слой данных)
Весь доступ к базе данных централизован в классе `Database.java`.
- **Механизм**: Используется JDBC для выполнения SQL-запросов.
- **Транзакции**: Для операций, затрагивающих несколько таблиц (например, добавление поступления товара с одновременным обновлением остатка), используются транзакции (`setAutoCommit(false)` $\rightarrow$ `commit()` / `rollback()`).

## 📊 Схема взаимодействия данных

```text
[Пользователь] <--> [FXML View] <--> [Controller] <--> [Database.java] <--> [MySQL DB]
                                        ^
                                        |
                                    [Model Classes]
```

## 🛠 Ключевые технические решения
- **Безопасность**: Использование `PreparedStatement` для защиты от SQL-инъекций.
- **Целостность**: Реализована проверка остатков перед списанием товара или созданием заказа.
- **Пользовательский опыт**: Реализована система ролей, которая ограничивает доступ к административным панелям для обычных пользователей.
